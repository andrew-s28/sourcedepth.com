## The Standard Library

You can do a lot with the Python standard library (the packages and functions bundled with any Python installation). However, you'll quickly find lots of things you can't do, or simply can't do as easily as you would like.

One typical example is the addition of two vectors. Using the `list` type available in the Python standard library, you might try something like the following:

```python showLineNumbers
list1 = [0, 1, 2]
list2 = [3, 4, 5]
print(list1 + list2)
```

Take a moment to see if you can figure out what you expect the output of this to be. When you're ready, you can find the output of the code above by clicking the "Show Answer" button below (or run the code yourself!).

<Spoiler label="Answer">
```python
[0, 1, 2, 3, 4, 5]
```
</Spoiler>

If you're anything like me, especially coming from a traditional mathematics background, then you might've guessed that the answer would be something like `[3, 5, 7]`. This "elementwise" or "pairwise" addition is not the default behavior for Python lists; in order to replicate it, you would need to do something like this<TooltipPopover number="5">Don't worry about the details here.</TooltipPopover>:

```python showLineNumbers
list1 = [0, 1, 2]
list2 = [3, 4, 5]
print([l1 + l2 for l1, l2 in zip(list1, list2)])
```

Now, I don't want to have to do that every time I need to add two vectors together. Luckily, [one of the core strengths of Python](/blog/posts/python-earth-science-intro#why-python?) is the vast open-source ecosystem of packages designed to simplify your life. Indeed, this might even enable us to *fly*!

## Using Python Dependencies

The best way to handle adding two vectors would be to use a package that provides this support built-in, such as [NumPy](https://numpy.org/). Let's try to make a new file in our project from the [last tutorial](/blog/posts/python-earth-science-intro#hello-world!). As a reminder, we created that in our home directory and can access it like so:

```bash
cd
mkdir hello_world
cd hello_world
```
Now create a new file named `add_vectors.py`, import the `numpy` package, and create our two arrays to add:

```python showLineNumbers
# add_vectors.py
import numpy as np  # first we import numpy so we have access to it's functions

# now we create "numpy arrays"
arr1 = np.array([0, 1, 2])
arr2 = np.array([3, 4, 5])

print(arr1 + arr2)
```

And let's run it:

```bash
uv run add_vectors.py
```

And - oh no! - we get the following error:

```bash
Traceback (most recent call last):
  File "~\hello_world\add_vectors.py", line 1, in <module>
    import numpy as np
ModuleNotFoundError: No module named 'numpy'
```

We can see that Python is reporting `ModuleNotFoundError`, which is exactly what it sounds like. While we've  tried to import NumPy in our script, we haven't downloaded the source code that gives Python access to NumPy. That's where virtual environments, managed by `uv`, come to the rescue.

## Managing Dependencies

The problem might seem simple to solve at first: we need some source code, we download it, and add it to our Python path. That works great when we have a handful of packages. But, what if one project needs NumPy version 1.23 and another requires NumPy version 2.1? Well, now we're stuck.

To solve this issue, Python includes support for virtual environments. These are essentially just directories (most often named `.venv`) that include a Python installation and additional packages like NumPy. These are separated on a per-project basis &mdash; that is, if you have two virtual environments in two separate folders, these are entirely distinct from one another, controlled by the dependencies listed in the `pyproject.toml` file in each folder.

In order to add dependencies to our project, we could manually type them into each `pyproject.toml`, but `uv` makes it easier:

```bash
uv add numpy
```

Now re-run the command `uv run add_vectors.py` and you should see the following printed without error:

```python
[3 5 7]
```

Indistinguishable from magic<TooltipPopover number="7">While it's not *really* magic, if you experienced [Python environment management before modern tooling](/blog/posts/nuke-conda), this truly feels revolutionary.</TooltipPopover>, as far as I'm concerned!

Now, if you open up your `pyproject.toml` file, it should look something like the following:

```toml
[project]
name = "hello-world"
version = "0.1.0"
requires-python = ">=3.13"
dependencies = [
    "numpy>=2.5.2",
]
```

We now see that `numpy>=2.5.2` is included in the dependencies. Since we didn't specify a version, `uv` chose the latest stable release (2.5.2) compatible with our minimum Python version (3.13). This is the beauty of `uv` - it manages this dependency section for us and, if any packages don't play nice together, it will let us know. Otherwise, we should never have to think about this again!

## Setting Up Your Project

Whenever I start a new project in the Earth sciences, I have a few must-have packages I install. If you're looking to get started quickly, running the following command whenever you initialize a new project should give you almost everything you'll need to get started:

```bash
uv add numpy xarray[accel,io,parallel] matplotlib ipykernel
```

You'll now have access to `import numpy as np`, `import xarray as xr`, and `import matplotlib.pyplot as plt`<TooltipPopover number="8">These are "conventional" imports and you should follow them.</TooltipPopover> as well as the interactive python kernel (`ipykernel`) for running Jupyter notebooks. These can be used within any scripts that you create within your project directory and even any subdirectories of our project directory.
